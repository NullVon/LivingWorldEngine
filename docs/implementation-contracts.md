# First milestone contracts

The two Word architecture records in this directory remain authoritative. Core Contracts v1 supplies the more specific ownership rules where the overview compresses Action effects into a single step.

## Records and authority

All persistent world participants and records use one Entity registry. An Entity has a stable `id`, opaque `type`, serializable `data`, `lifecycle`, optional `primaryLocation` and `container`, and optional structural components (`actor`, `situation`, `claim`, `attempt`, `event`, `consequence`). Relations and Globals use the structures explicitly allowed by the World State contract. Scene frames, pending input, queue IDs, counters, and checkpoint status are engine control in the save envelope, not fictional world truth.

Bootstrap is the sole direct initialization operation. The public API never exposes a mutable runtime. Action submission queues an attempt; it does not resolve it or advance the world. Resolution is synchronous and atomic at a Scene boundary. Shell callbacks receive detached, recursively frozen values. An exception rolls the boundary back, including its IDs and queues. Shell callbacks must be synchronous, deterministic and free of external side effects. A completed Scene boundary is a safe serialization checkpoint even when its causal budget leaves deterministic pending work for a later boundary; active or suspended Scenes are not checkpoints.

At a stable checkpoint, `deferAttempts(attempts, due)` may place a nonempty Action batch into serializable control state for a future boundary. Due batches enter resolution before attempts submitted in that Scene and are removed in the same atomic transaction that resolves them. Their Action eligibility, Shell conflict grouping, seeded arbitration, Events, and Consequences use the ordinary pipeline. Persistence retains the batches and random state, so restoration neither rerolls nor duplicates them. This queue does not make active or suspended Scenes saveable, and there is no persistence checkpoint after only part of a conflict has resolved.

## Causal flow

Scene → attempt → objective Event → Consequence → structural mutation. World processes may originate Events. Later Events must name a Consequence as their cause. Events may also retain multiple contributing historical references. Consequences store before/after changes and execution status. A WHY query follows those references, including the claims that informed an attempt. Rejected attempts produce failed Events, not their intended changes.

## Shell interfaces

`actions[type]` supplies optional `eligible(context)` and, for Shell Actions, `resolve(context)` functions. Resolution context includes objective state for adjudication. Human input and selected autonomous attempts converge on the same resolver. Universal Action semantics are fixed by Core; Shell eligibility may permit or forbid them but may not redefine their effects. A normal `false` eligibility result makes an Action unavailable or produces a failed Action Event. Exceptions and malformed hook results are implementation failures: Core exposes them and rolls back the boundary rather than silently treating them as ordinary denial.

Eligibility receives `phase: 'selection'` while Core filters dynamic autonomous candidates and `phase: 'resolution'` immediately before an attempt resolves. The Shell may allow a belief-supported candidate during selection while rejecting it against authoritative state during resolution. Submitted attempts are also revalidated at resolution. After each ordered attempt, Core settles its immediate Consequences and Situation changes before revalidating the next attempt.

`conflicts({attempts, world, boundary})` is the optional objective adjudication hook for pending attempts in one Scene. It returns competing groups with a stable `id`, entries containing an attempt `index`, numeric Shell-defined `value`, and optional nonnegative random-tie `weight`. `direction` is `high-first` or `low-first`. Equal values use an explicit tie policy: `actor-order` (with an optional Actor ID order), seeded `random`, `no-winner`, or `simultaneous`. Simultaneous means a tied tier keeps submission order and each attempt still passes normal immediate revalidation, so it is suitable only when the Shell regards the outcomes as compatible. Core records conflict rank and policy without interpreting the values. Attempts outside a group retain their submitted order. An attempt may belong to at most one group.

The read-only autonomous Decision Context is a safe projection rather than Objective World State. It contains the Actor's identity, controller, Shell-defined Entity data, primary location and containing Entity; structural summaries for possessions nested beneath that Actor; the Actor View; aware Situation IDs and the Actor's claims about them; `decision.shared` plus that Actor's entry under `decision.actors` from the current Scene context; dynamically eligible Action attempts; opaque Shell desire IDs/weights; and the boundary number. It omits the world registry, Globals, Relations, unseen Entities, unknown Situations, and objective Situation state. `available(context)` supplies dynamic candidates through the normal eligibility interface. `desires(context)` supplies opaque `{id, weight}` records. `choices(context)` selects from those available attempts and may associate an attempt with a desire ID; Core uses the corresponding weight for probabilistic selection with an instance-local seeded generator.

`perceive({event, world})` returns explicit Actor claim grants. Co-location does not grant perception. Communicate transfers a supplied claim (which can be false) and records its source and lineage. A Situation-directed Action requires an active awareness claim about that Situation. `evidence` references must belong to the acting Actor's current View; objective IDs alone cannot authorize informed reaction.

`worldProcesses({world, boundary})` returns root Event specifications at progression boundaries. `offscreenActors({boundary})` returns an ordered list of Actor IDs; its length is bounded by the caller's explicit off-screen budget. Each decision is made after the preceding Action's consequences stabilize so communication can inform a later Actor in the same window.

Situation Entities declare at least one terminal path: a generic predicate plus a terminal lifecycle. A path may have an `id`; when it fires, that ID is preserved on the objective `situation.changed` Event. Optional expiry provides another terminal path. Important Situations must declare a Shell-authored opportunity (recipient Actor plus a legitimately disclosable claim) and the Shell must provide `surfaceOpportunity({boundary, situation, previousCount, world})`. Each `true` response creates a new objective opportunity Event and transfers the declared claim. Core suppresses duplicate delivery within one boundary but imposes no lifetime count; cadence and repetition belong to the Shell. This world-policy hook may inspect read-only Objective World State; it is not an autonomous Decision Context. Hidden truth is not copied into the opportunity. Shell is responsible for the legitimacy and meaning of the disclosure.

The conflict hook is trusted objective adjudication and may inspect its read-only World State input. Its objective facts never enter Actor View or autonomous Decision Context without a separate legitimate information Event.

## Minimal scope and choices

Universal Actions: Move, Take, Give, Communicate, Interact, Wait. Move accepts no target and changes only the acting Actor's primary location. Moving another Entity is a Shell Action that may produce the generic `move` Consequence operation. Give may transfer an Entity anywhere within the acting Actor's transitive containment tree. Interact produces a meaningful resolved Action Event but has no default World State effect; Shell `consequences({event, world})` may respond to that Event through ordinary Consequences. Specialized effects are Shell resolvers. Contests are generic numeric ordering with explicit tied groups. Predicates are small JSON expressions, never evaluated code.

Consequence operations: create, retire, set Entity data, move, contain, upsert Relation, set Global, grant/forget a claim, change Situation state, emit a later Event. Each specification can be delayed to a boundary and have a predicate rechecked when due. Invalid delayed work is recorded once and removed from the queue. Queued work can cross windows under a Shell budget and is serialized at completed Scene boundaries, including work already due but deferred by the budget. Restored processing remains deterministic because the queue, boundary, causal records, execution counter and random state are persisted. A hard operation ceiling and causal-depth ceiling stop runaway chains.

Scenes support nested interruption frames and explicit resume/transform/end. A nested Scene may change authoritative state before the parent resolves. Resume preserves the parent context and attempts; transform replaces its context while preserving its attempts; both attach nested applied Consequences as causes of subsequent parent outcomes and revalidate normally. End records one `action.cancelled` Event for every pending parent attempt, with the nested Consequences as causes, then removes that frame. Active and suspended frames remain unsaveable. Fictional time is Shell data changed through Consequences. No timers or real-time loop exist. Multiple windows must be advanced individually.

Save/load uses a versioned JSON envelope and structural validation. Version 1 has no older schema to migrate; unknown versions are rejected. Shell functions are supplied again on restore. Dice is deferred and is not a dependency. History compaction, semantic contradiction handling, rich retention policies, automatic emergent interruption detection, and sophisticated Situation evolution are outside this milestone.
